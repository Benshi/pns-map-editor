# P&S ギルドマップエディター

Puzzle & Survival のギルド施設・メンバー避難所を配置する、日本語の Web アプリです。外部サービス・外部ライブラリは不要です。

## 起動

Node.js 22 と Python 3 がある環境では `npm start` を実行し、`http://localhost:8080` を開きます。静的ファイルを HTTPS の Web サーバー（GitHub Pages など）に配置しても利用できます。`file://` から直接開く方法には対応していません。

初回オンラインアクセス時にアプリをキャッシュします。「オフライン利用の準備ができました」と表示されたら、ネットワークなしでも同じ URL を開けます。対応ブラウザーではホーム画面への追加も可能です。Service Worker は HTTPS または localhost が必要です。

## 編集・保存・共有

1. ギルド名を入力してギルドを追加します。最初のギルドが自ギルドになります。別のギルドも追加でき、自ギルドは変更可能です。
2. 所属メンバーを最大100名登録します。避難所を配置する際はメンバーを選択します。
3. 施設と座標を選び「この座標に配置」、またはマップ操作を「クリックで配置」に切り替えてマップをクリックします。要塞の配置時にはギルド名を確認・入力します。
4. 施設の4マスのどこをクリックしても選択できます。施設一覧からも選択でき、入力座標への移動・削除ができます。
5. ドラッグまたは矢印キーで画面移動、ホイールまたは＋／−で拡大縮小します。「全体表示」「自ギルドへ」「座標へ移動」も利用できます。

変更はブラウザーの localStorage に自動保存されます。保存できない場合は警告を表示します。保存データは URL のオリジン・ブラウザーごとに独立しており、ブラウザーデータの削除で失われます。**JSON を定期的に保存してバックアップしてください。**

「JSON を共有・保存」でダウンロードしたファイルを他の人に送ると、相手は「JSON を読み込み」で編集できます。読み込みは現在のマップ全体を置き換えます（確認あり）。不正な座標・重複占有・メンバー不整合などは読み込み時にも検証します。共同リアルタイム編集は行いません。

## マップのルール

- X:0〜511、Y:0〜1023。同じ奇偶の座標のみ存在し、入力・クリックは最寄りの有効座標へ丸めます。同距離の場合は小さい X、次に小さい Y を選びます。
- 正方形のマスを45度回転して描画します。指定された座標範囲は縦が横の約2倍なので、**全体の外形は縦長**です。「正方形マップ」と指定座標範囲との矛盾については、座標範囲とマスの形を優先しています。
- 2×2 施設の基準座標は南セルです。占有セルは `(x,y)`, `(x-1,y-1)`, `(x,y-2)`, `(x+1,y-1)` です。配置・移動時は4セルすべてを検証します。施設同士・山岳との重複は禁止です。
- 要塞・資源・トラップ・倉庫・病院は各ギルドに一つ。資源は種類・ギルドレベルを問わない単一の「ギルド資源」として扱います。避難所は所属メンバー一人に一つです。今回指定された施設はすべて2×2です。
- 実験基地外囲と荒地は指定の頂点で判定します。境界セルも内側として扱い、ギルド施設は4セルすべてが緑地の場合のみ配置可能です。
- 要塞の南セルから X・Y それぞれ±12が領地です。荒地・基地・山岳を除外します。自ギルドは明るい黄緑、他ギルドは暗い朱色、複数ギルドの共有領域は黄土色です。
- **山岳の実座標データは提供されていません。**「山岳（進入禁止）」で実際の位置を2×2単位で登録・移動・削除してください。JSON にも保存されます。架空の山岳位置は初期配置していません。
- 広域表示ではグリッドと施設名を省略します。拡大すると避難所のプレイヤー名・要塞のギルド名などが表示されます。

## 検証

`npm test` は Node.js 標準のテストランナーで座標・地形・占有・ギルド・メンバー・JSON 検証を実行します。`npm run check` は JavaScript の構文検査です。依存関係のインストールやビルドは不要です。
