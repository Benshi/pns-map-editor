# P&S ギルドマップエディター

Puzzle & Survival のギルド施設・メンバー避難所を配置する、日本語の Web アプリです。外部サービス・外部ライブラリは不要です。

## 操作状態・検索・利用者の登録日時

- ギルド未選択時は通常、山岳だけを配置対象にできます。例外として「プレイヤー管理」から未所属プレイヤーの避難所を指定した場合は、避難所の配置・移動もできます。ギルド施設の配置にはギルド選択が必要です。
- マップ上の「選択解除・閲覧」または Esc で選択・配置プレビューを解除し、閲覧モードにします。このモードでは施設の上からドラッグしても画面移動となり、クリック配置や施設移動をしません。配置を再開するには配置対象と「クリックで配置」を選びます。
- マップ上に「配置待機中」「施設選択中」「施設移動中」「閲覧・画面移動」などの状態をアイコン付きで表示します。PCのカーソルは配置時に十字、選択施設上で移動カーソル、閲覧時に手の形になります。
- 拡大率は通常の表示倍率（scale 14）を100%として、ホイール・ピンチ操作中も表示します。全体表示でも操作状態・閲覧ボタン・拡大率は表示します。
- 領地コンテキストメニューでは各ギルドコードの右に「総勢n名」を表示します。
- 「施設を探す」の凡例色付きチェックボックスで種類を複数選択して絞り込めます。要塞・前哨・避難所・資源・響罠・倉庫・病院の7種類を同じサイズで並べ、初期状態はすべてチェック済みです。全解除すると検索結果は0件になり、山岳は検索対象に含めません。名前・ギルド・座標の検索と併用できます。ダイアログは上寄せし、結果一覧と追加表示ボタンの領域を確保するため、結果件数が変わっても操作位置が動きません。
- 新規ユーザーは初回Googleログイン時の登録日時をUTCで記録し、管理者の利用者一覧に日本時間で表示します。登録日時が不明な既存ユーザーは空欄とし、再ログイン・表示名変更・編集停止でも登録日時を変更しません。

## 起動

共有編集には PHP 8.3 の API と非公開データ領域を配置します（下記参照）。Node.js 22 と Python 3 がある環境では `npm start` を実行し、`http://localhost:8080/?storage=local` を開くと、API を使わない端末内編集を確認できます。静的ファイルを HTTPS の Web サーバー（GitHub Pages など）に配置する場合も `?storage=local` が必要です。`file://` から直接開く方法には対応していません。

初回オンラインアクセス時にアプリ画面をキャッシュします。共有マップの読み込み・保存には通信が必要で、オフライン共有編集や同期は未対応です。対応ブラウザーではホーム画面への追加も可能です。Service Worker は HTTPS または localhost が必要です。API・共有データはキャッシュ対象にしません。

静的ファイルの更新では関連ファイルを一式アップロードし、`sw.js` は最後に更新してください。キャッシュの取得はHTTPキャッシュを再利用せず行い、更新処理はアプリ本体のモジュール読み込み失敗時にも動作します。更新通知後は未保存の変更をJSONで退避し、再読み込みしてください。`does not provide an export named` エラーで起動しない場合はファイルの版違いが疑われます。アップロード完了後、Chrome開発者ツールの Application → Service Workers → Update を実行し、更新完了後に再読み込みしてください。それでも古いキャッシュが残る場合は当該サイトの Service Worker を Unregister し、Cache Storage 内の `pns-map-editor-` で始まるキャッシュだけを削除して再読み込みします。端末内マップや選択設定を保持するため、Local Storage やサイトデータ全体は削除しないでください。

## 編集・保存・共有

山岳は2×2の基準座標を保持し、荒地と重なるマスだけを除外します。境界上では1〜3マスの形状になり、4マスすべてが緑地の位置へ移すと通常形状に戻ります。選択・重複・領地判定と描画は実占有マスだけを対象にし、外周の余白は一体の形状に付けます。山岳の座標は消えた南マスも含む「基準座標」で、ラベルは残った形状の中央に表示します。ドラッグは掴んだ位置からの移動量を基準座標へ加算します。全マスが荒地の山岳、実験基地外囲に重なる山岳は配置できません。形状が復帰する移動先で他の施設と重なる場合も移動できません。

配置・ドラッグ移動・座標移動のプレビューは、施設・山岳の種類別カラーを不透明度60%で描画し、白い破線で囲みます。配置不可の場合は赤い半透明表示と赤枠に切り替えます。既存施設と同じ位置では塗りを重ねず白枠のみを表示します。

ギルド管理では「新規ギルドの追加」と「管理対象：[コード]」を分けて表示します。新規コード欄には選択中ギルドのコードを入れません。コードの入力だけではギルドは追加されず、「ギルドを追加」で確定すると管理対象が新しいギルドに切り替わります。未追加のコードを入力中は既存ギルドのコード変更・削除・プレイヤー管理への入口を無効にし、追加するか入力を空にするよう案内します。ギルド削除時はギルド施設だけを削除し、所属プレイヤーはランクを解除して未所属にします。プレイヤーと避難所は残します。

「施設を探す」で現在のサーバーの施設・避難所を名前・ギルドコード・座標の部分一致で検索し、結果を選ぶとその位置へ移動して選択します。検索結果には凡例と同じ色の施設アイコンを表示し、大量データでは100件ずつ追加表示します。「選択解除」で配置指定も解除できます。

「プレイヤー管理」はギルド選択・ギルド管理ボタンの下から開きます。避難所パネル内に管理ボタンは置きません。ダイアログの「所属」は登録済みギルドと「未所属」から一覧の表示対象を選ぶもので、マップの選択ギルドやプレイヤーの所属は変更しません。初期表示はマップで選択中のギルド、未選択なら未所属です。名前検索、総勢・配置済・未配置人数とランク別一覧を表示し、最上位の登録者がいるランクを初期展開します。同ランク内はプレイヤー登録順です。未所属はランク未設定の一覧だけを表示します。「プレイヤー登録」を押したときだけ一括入力欄を表示し、チェックで対象を選んだときだけランク変更・削除欄を表示します。個人の行を押すと、名前変更・避難所の配置／表示・所属変更を行う小さな編集画面を開きます。タブ区切りのメンバー表は別の折りたたみ欄からコピーできます。「未配置」は登録済みだが避難所がない状態で、未登録とは異なります。

プレイヤーはサーバー単位の固有IDで管理し、現在所属するギルドは未所属（null）も許可します。避難所はプレイヤーIDだけに紐付け、所属変更で座標や施設IDを変更しません。避難所の右クリック／ロングタップメニューでは、所属ありなら「ギルドから脱退」「別ギルドへ移籍」、未所属なら「ギルドに加盟」を表示します。脱退は確認後にランクを解除します。加盟・移籍では変更先ギルドと新しいランクを指定し、旧ランクは自動継承しません。ギルド人数・所属一覧・表示色は現在所属に従います。同じ所属の同名登録・同名者がいる所属への変更は拒否し、IDだけで人物を識別します。脱退・移籍は各1回のUndoで戻せます。未所属にはランクを設定できません。登録・所属変更・削除は編集権限が必要です。

保存形式はv2です。ギルドは `guilds`、プレイヤーは `players`（`id`・`name`・nullableの `guildId`・任意の `rank`）で独立して保存し、避難所は `playerId`、ギルド施設は `guildId` を参照します。v1のギルド内 `members` と避難所の `memberId` は、読み込み時に既存ID・名前・ランク・座標を保持してv2へ変換します。共有保存・過去版の復元もv2として新しい版を保存し、既存履歴ファイルは書き換えません。更新前にJSONと非公開データ領域をバックアップし、PHPと静的ファイルを同じ版へ更新してください。v2は旧アプリ・旧APIでは読み込めません。`sw.js` は一式の配置完了後に更新します。

PC・スマホとも施設をクリック／タップで選択し、その施設を次のドラッグで移動できます。空き地や未選択施設からのドラッグは画面移動です。クリック配置モードでも既存施設をタップすると選択モードに戻ります。移動中は半透明・破線の予定位置を表示し、指を離したときに確定します。禁止地形・重複の場合はエラーを表示して元の位置を維持し、タッチ操作の中断も確定しません。1回の移動は1回のUndoで戻せます。配置モードでは要塞・領地につながる前哨の配置予定中も領地の塗りと外周フレームをプレビューし、前哨の予定領地は半透明で重ねて既存領地の色も見えるようにします。施設の右クリック、またはスマホでのロングタップから操作メニューを開けます。メニューの先頭に `[ギルドコード]施設名` と `S:サーバー番号 X:座標 Y:座標` を表示し、削除できます。避難所ではメンバーのランク・名前変更、要塞ではギルドコード変更も同じメニューから行えます。閲覧専用時も画面移動・拡縮・施設選択は可能ですが、配置コンソールと編集ボタンを非表示にします。
未配置のメンバーや施設を選ぶと、自動的に「クリックで配置」モードになります。「この座標に配置」で配置した後は選択を解除し、配置前の操作モードを維持します。クリック配置モードだった場合は、続けてマップクリックで配置できます。配置済み施設のドラッグ移動後は選択状態を維持します。スマホでも同じで、画面キーボードが勝手に開かないよう座標欄には自動フォーカスしません。未保存の編集があると、画面上部の「保存」ボタンが点滅して場所を示します（端末の「視差効果を減らす」設定時は点灯表示）。
新規配置プレビュー中に Esc キーを押すと、プレビューとオブジェクト選択を解除します。

領地色は対象セルを塗りつぶし、施設・山岳は施設全体の外周を少し内側に描画します。複数マスの施設も内部を分割せず一体で塗るため、余白は外周だけにでき、施設同士の間や領地色との境目が見やすくなります。隙間から地面または領地色が見えるため、配置位置が緑地・自ギルド・他ギルド領地のどこにあるかを判別できます。余白は表示上だけで、領地の範囲・施設の配置判定には影響しません。避難所以外の施設・山岳の内側の区切り線と選択枠は細線で表示します。配置中でないときに領地をクリックすると、その領地のギルドを選択し、競合領域なら選択を解除します。クリック配置モードで配置プレビューが有効な間は、自ギルド・他ギルド・競合領地のいずれでも施設配置を優先し、選択ギルドを変更しません。地形・施設重複の配置制限は従来どおりです。領地の右クリック／ロングタップメニューには該当するギルドコード（競合領域では全ギルド）とクリック座標を表示します。要塞・要塞につながった前哨を選択すると、その施設単独の領地境界をピンクで強調します。他ギルドとの共有範囲も含め、山岳・荒地・実験基地外囲を除いたセルの外周と穴の境界を表示します。未接続前哨には領地境界を表示しません。配置済みの施設・メンバーの避難所を別座標に配置すると、移動確認後に同じIDのまま移動します。キャンセル・配置不可の場合は元の施設を維持し、移動は1回のUndoで戻せます。

カテゴリ・施設の切替やマウスホバーだけでは配置済み施設の移動プレビューを開始しません。既存施設のプレビューはドラッグまたは座標入力時に表示し、入力座標のプレビューはマウスに追従しません。施設削除後は選択を解除します。

ギルド施設の配置一覧もメンバー一覧と同様に、未配置は淡い黄色、配置済みは青灰色で表示します。山岳には配置状態の着色をしません。ネイティブ選択欄の文字色はOS・ブラウザーによって反映されない場合があるため、配置済みの文字表示も維持します。

施設の各セルに濃い輪郭を付け、隣り合う施設の区画を見分けやすくします。避難所は共通の青地にランク別の中央×線（R5は赤、R4は金、R3は紫、R2は緑、R1は青、未設定は白）を重ね、凡例にも同じ×線の見本を表示します。マップ外は暗い色、マップ内は有効セルの輪郭に沿って塗り、四辺のギザギザした境界を示します。

「メニュー」にログイン・JSON入出力・保存版の詳細をまとめます。最新版の読み込みはPCではヘッダーから直接実行でき、スマホではメニュー内にあります。画面下部には固定通知領域を確保し、操作結果を常に確認できます。スマホでは上部と補足文を圧縮し、マップの領域を確保します。幅500px以下・高さ700px以下の画面ではタイトル行だけをスクロール時に固定し、編集パネルは画面下のつまみから引き出せるスクロール式ドロワーになります。2本指のピンチで拡縮・中心の移動ができ、施設ドラッグ中に2本目の指を置くと施設移動を取り消してピンチに切り替えます。指をすべて離すまで配置・移動の確定をしません。

ログイン・利用者設定画面の「マップに戻る」は未ログインでも使用できます。マップから開いた場合、共有コード・ギルド・拡大率など元のURLパラメーターを保持して戻ります。設定画面を直接開いた場合はマップの入口へ戻ります。

「全体表示」は拡大率を変えず、サイドメニュー・操作ボタンを隠してブラウザーの表示領域いっぱいにマップを表示します。マップを縮小して全域を収める機能ではありません。ドラッグ・スワイプで画面移動でき、選択施設の上からも施設移動ではなく画面移動になります。新規配置も行いません。右上の復帰アイコンまたはEscで元のレイアウトへ戻り、表示位置・拡大率・編集内容は維持します。ホイール・ピンチ拡縮は引き続き使用できます。ブラウザー自体のアドレスバーは隠しません。選択した施設名は縮小表示でも最後に描画し、ピンクの文字と暗い背景で他の文字より前面に強調します。

共有URLの形式: `?map=Abc123_-xyzQ&guild=AbC`（コードは形式例）。`map` は12文字のランダム共有コードです。サーバー番号・ハッシュは共有URLに含めません。`guild` は**大小文字を区別する**ASCII3文字のギルドコード、任意の `scale` は0.3〜40（1座標あたりの画面ピクセル数・既定14）、`revision` は1以上の保存版番号です。`?map=Abc123_-xyzQ&guild=AbC&revision=12` のように指定すると第12版を閲覧専用で読み込みます。存在しない版番号はエラーになります。履歴画面から過去版を開いた場合もURLに `revision` を設定し、最新版へ戻る・別サーバーへ切り替えると削除します。地図読み込み後、指定ギルドの要塞を中央に表示します。ギルド指定なし・要塞未配置は中央基地(256,512)へ初期表示します。ギルド選択の端末設定よりURLを優先し、共有地図を変更しません。不正なパラメーターはエラーを表示し、見つからないギルドはエラーと中央表示にします。`map` と `server` は同時指定できません。端末内モードでは共有コード・サーバー指定を使わず、端末内地図にギルド・拡大率指定を適用します。端末内地図には保存履歴がないため `revision` 指定はできません。

管理者以外は `map` または編集者用の `server` が必要で、未指定なら最初に共有コード／サーバー番号入力画面を表示します。閲覧者は共有コードのみ使用でき、サーバー番号だけでのAPIアクセスは登録済み・未登録を問わず拒否します。サーバードロップダウンには開いたサーバー1件だけを表示し、管理者のみ全登録サーバーを切り替えられます。編集権限者・管理者は `?server=1063`（`S1063` 形式も可）で任意のサーバーを開けます。未登録番号は空マップを表示し、編集権限者が保存すると新規登録します（空のままの初回保存も可能）。

共有コードはサーバー番号から計算せず、サーバーごとに暗号学的乱数（72ビット）から生成した12文字のURL安全なコードです。コードは大小文字を区別します。既存サーバーは編集権限者・管理者が初めて開いた時、新規サーバーは初回保存時に発行し、非公開 `maps/S番号/share-code.json` に保存します。地図読み込み・ギルド登録／選択・初回保存後にアドレスバーを短い共有URLへ自動更新します。閲覧用URLはこのアドレスバーからコピーしてください。APIは共有コードからサーバーを特定し、地図・一覧・履歴・過去版すべてで対応サーバー以外の閲覧を拒否します。

これは**共有リンクを知っている人が閲覧できる簡易保護**です。番号の推測では他サーバーを開けませんが、コードの漏えい・転送による閲覧を防ぐ個人別認証ではありません。個人別の閲覧許可・有効期限・共有コード再発行UIはありません。URLはブラウザー履歴やWebサーバーのアクセスログに残る可能性があります。外部サイトにはRefererを送らない設定ですが、リンクの取り扱いには注意してください。旧 `server`＋`hash` 閲覧URLは使用できません。更新後に編集権限者が `?server=番号` で開いて新しい短い共有URLを配布してください。旧非公開 `share.json` は使わず、そのまま保持します。

要塞のドラッグ中は領地も移動予定座標でリアルタイム表示します。緑地・山岳による除外と他ギルド領地との重複色も再計算します。配置不可の位置でも予定領地は確認でき、移動取り消し時には元の領地へ戻ります。ドラッグ中は保存データを変更しません。

要塞未配置のギルドでは、新規要塞のホバー・座標入力プレビューにも予定領地を表示します。領地の計算はドラッグ中と共通で、配置確定までデータを変更しません。要塞配置済みのギルドに二つ目の予定領地は表示しません。

配置候補が既存施設と種類・所属ギルド・メンバー・サイズ・基準座標まで一致する場合は、白い枠と「選択中」で表示します。同じ候補を再度配置しても既存施設を選択するだけで、データやUndo履歴を追加しません。別施設との重複や、配置済み施設を別座標へ新規配置する操作は従来どおり拒否します。移動には施設の移動操作を使用してください。

「選択解除」を押すか、選択モードで空きマスをクリックすると、配置プレビューを解除し、マップ操作を「選択・移動」に戻します。配置対象・メンバー・座標を改めて指定するか、「クリックで配置」に切り替えるとプレビューを再開します。

ギルド作成・選択・選択の復元時は「クリックで配置」に切り替えます。ギルド未選択なら山岳、要塞未配置ならギルド要塞、要塞配置済みなら避難所を初期配置対象にします。リアルタイム座標はマップ左上の拡縮ボタンより左に表示します。グリッド内の参考座標は文字列の中央をセル中央へ揃えます。

1. 初期状態はギルド未選択・「山岳」です。ギルドのドロップダウン横の「ギルド管理」で、ASCIIの表示可能な3文字のギルドコードを追加・変更・削除します。選択中ギルドのメンバー登録・管理も、この画面の「選択ギルドのメンバー管理」から開けます。コード変更では旧コードを一覧から選択でき、現在選択中のギルドが初期選択されます。既存コードとの重複や変更前と同じコードは受け付けません。現在のデータ形式ではギルドの `name` にコードを保存します。既存の長い名前は自動切り詰めせず保持します。ギルドは登録順で表示し、ギルド管理の「ギルドの並び順」で登録順・ギルドコードの昇順を切り替えられます。この表示設定は端末のlocalStorageに保存し、共有マップには含めません。選択中のギルドを自ギルドとして色分け・「自ギルドへ」の移動に使用し、未選択なら自ギルドなしとして扱います。選択は利用者・サーバーごとに端末へ記憶し、共有地図の変更とは扱いません。
2. 「避難所」タブで所属メンバーを選びます。登録はギルド選択欄の下の「プレイヤー管理」から行います。所属の表示対象を選び、「プレイヤー登録」で1行に1人の改行区切りペーストを入力します。ギルド所属ならR5〜R1または未設定、未所属ならランクなしで登録します。空行は無視し、同じ所属の既存の同名・入力内の同名はスキップして、新規登録人数とスキップ人数を報告します。既存プレイヤーのランク・ID・登録順は変更しません。不正な名前があれば全体を拒否します。同名だけの入力は履歴を増やしません。名前・ランク変更はIDと避難所位置を維持し、プレイヤー削除は確認後に避難所も削除します。
3. 「山岳」「避難所」「ギルド施設」のタブで配置対象を切り替えます。ギルド未選択でも山岳は編集できます。未所属の避難所は「プレイヤー管理」で対象者を開き、「避難所を配置・表示」から指定します。ギルド施設の配置にはギルド選択が必要です。施設と座標を選び「この座標に配置」、またはマップ操作を「クリックで配置」に切り替えてマップをクリックします。編集中は入力座標に配置予定の占有マスを半透明・破線で表示し、施設名（避難所はプレイヤー名）と座標を添えます。クリック配置モードではカーソル位置を優先します。配置不可は赤色で表示します。画面外の座標は「座標へ移動」で確認できます。プレビューは地図データを変更せず、閲覧専用時には表示しません。
4. 施設の占有マスのどこをクリックしても選択できます。「施設を探す」から名前・ギルド・座標で検索して選択でき、入力座標への移動・削除ができます。
5. ドラッグまたは矢印キーで画面移動、ホイールまたは＋／−で拡大縮小します。「全体表示」「自ギルドへ」「座標へ移動」も利用できます。

メンバー一覧は R5→R4→R3→R2→R1→未設定の順、同ランク内は登録順です。旧データのランクは推測せず「ランク未設定」として保持します。ランク別一覧はアコーディオンで、検索中は一致するグループを展開します。見出しには総勢・配置済・未配置人数を表示し、選択中の人数は強調色で括弧表示します。「メンバー表（Excel用）」にはランク・名前・配置状態・X・Yのタブ区切り一覧が表示され、「一覧をコピー」でクリップボードへコピーできます。

R5はギルドマスター（ゲーム内1人）、R4は運営メンバー（参考上限20人・うち官職0〜4人）、R1〜R3にランク別人数制限はありません。総数100人・R5の1人・R4の20人を超えた場合は該当行の総人数のみ赤く表示し、超過登録・ランク変更・JSON読み込み・共有保存を許可します。管理画面は説明・重複集計を省き、各ランク見出しに全人数・配置済み・未配置人数をまとめます。0人のグループも表示します。絞り込み中も人数はグループ全体の値です。官職の個別登録は未対応です。

プレイヤー管理のチェックボックスで複数人を選び、表示された操作欄からランク変更・削除ができます。「一括選択」は検索中に検索対象外のプレイヤーも選択するか確認します。「すべて解除」は折りたたみ中や検索対象外を含むすべての選択を解除します。検索で非表示になった選択も選択人数に含まれます。選択はダイアログを開き直す・表示対象の所属を切り替えると解除します。「メンバー削除」は確認画面に対象者と避難所座標を示し、確定するとプレイヤーとその避難所を削除します。一括変更・削除は各1回のUndoで戻せます。一括ランク変更は名前・ID・登録順・避難所の位置を維持します。

各ポップアップの右上に「×」の閉じるボタンを固定表示し、内容をスクロールしても操作できます。

配置カテゴリの3ボタンは山岳がグレー、避難所が青、ギルド施設が緑系の固定色・固定高さ・1行表示です。選択に合わせてコンソール背景をそのボタンと同じ色に切り替え、選択ボタンは内枠で示します。選択施設情報・凡例の背景は変更しません。

ギルド施設の選択肢は、選択中ギルドで配置済みの施設に「配置済み」を表示します。前哨は番号ごとに判定し、配置・削除・Undo/Redo・ギルド切り替えで更新します。山岳には配置済みマークを付けません。

メンバーの選択肢は配置済みを落ち着いた青灰色、未配置を淡い黄色で表示します。OS・ブラウザーの標準選択画面では色が反映されない場合があるため、「配置済み」「未配置」の文字も維持します。未所属の避難所名は白系の文字で、ギルドコードを付けずに表示します。

施設の色は所属ではなく種類別です。凡例は2列で、地形・領地とギルド施設の間に区切りを設けます。地形は緑地・荒地・山岳・実験基地外囲・砲台・中央基地の順、領地は自ギルドを左、他ギルドを右に並べ、その下に「複数ギルドで競合する領地」を全幅で表示します。施設凡例はギルド要塞（金色・太枠）とギルド前哨（橙）を左右に並べ、響罠[スピーカートラップ]（赤）と避難所（共通の青地）を各全幅で表示します。避難所ランク凡例は避難所の下に置き、続けてギルド資源（深緑）とギルド倉庫（紫）、最後にギルド病院（青緑）を表示します。避難所にはランク色の中央線を重ねます。同種の施設は同じ色です。所属は領地色と避難所名の文字色で区別します。自ギルドの名前はマリンブルー、他ギルドは黄色の `[コード]名前` です。「ギルド施設」の選択肢に前哨1〜5（各1×1・各ギルド各番号一つ）があります。前哨の配置・ドラッグでも接続先を含めた領地をプレビューします。

初期表示は共有コードまたは編集者用URLで指定したサーバーです。管理者が指定なしで開いた場合のみ、登録済みの **S1063** を優先します。一般ユーザーは未指定時に共有コード、編集者なら番号も入力できます。ギルド・メンバー・施設・山岳の編集は「保存」を押すまで共有データに反映されません。「未保存」表示を確認してください。未ログインでも共有URLで地図を閲覧でき、Google ログインと表示名登録が済み、編集停止されていない利用者は保存できます。

保存前の操作は Undo / Redo で戻せます（最大100操作）。「保存履歴・過去版の閲覧」では最新100件の履歴を取得し、過去版を閲覧できます。過去版は閲覧専用で、編集再開には「最新版を読み込む」を使います。復元は新しい版として保存し、既存履歴を残します。画面には表示中の版・更新日時・保存時点の表示名と識別名を表示します。同じ版からの競合保存は拒否し、手元の変更は残します。JSON に退避してから最新版を読み込み、必要な変更を再適用してください。自動マージは行いません。

自ギルドと選択ギルドは、利用者・サーバーごとにこのブラウザーの localStorage に記憶します。他の端末への設定同期は未対応です。自ギルド設定は共有地図を変更しません。ギルドを選ぶと、登録済みの要塞へフォーカスします。

端末内モードも明示的な「保存」で localStorage に保存します。旧版の `pns-map-editor-v1` 保存データは共有モードで自動上書きしません。`?storage=local` で開いて JSON バックアップを取得し、共有モードで対象サーバーを選んで読み込んでください。JSON 読み込みは地図全体を置き換えるため、他者のデータがある場合は慎重に使用してください。**JSON を定期的に保存してバックアップしてください。**

「JSON を共有・保存」でダウンロードしたファイルを他の人に送ると、相手は「JSON を読み込み」で編集できます。読み込みは現在のマップ全体を置き換えます（確認あり）。不正な座標・重複占有・メンバー不整合などは読み込み時にも検証します。共同リアルタイム編集は行いません。

## サーバー別マップ・閲覧・検索の追加予定仕様

以下は実装済み機能と追加予定仕様です。サーバー切り替え・共有閲覧・保存は実装済みです。全体表示での避難所の点灯・名前検索は未実装です。

### サーバーとギルド（alliance）の選択

- ゲームサーバーは現時点で約1300あり、それぞれに数十のギルド、各ギルドに数人〜100人のプレイヤーが存在します。各ギルドのメンバーが自分たちの周辺を作成・メンテナンスすることを想定し、サーバー全域の地図作成は必須にしません。
- サーバーを選択した後、そのサーバー内のギルド一覧からギルド（alliance）を選択し、対象ギルドの施設・避難所を配置します。
- データはギルドごとの独立したマップではなく、サーバー共通の地図として管理します。
- ギルドの選択状態は利用者アカウント・サーバーごとに保持し、サーバーを切り替えて戻ったときは、前回選択していた自ギルドを継続選択します。他の利用者の選択状態は変更しません。
- ギルドを選択すると、そのギルドの要塞の周辺にフォーカスします。
- 同じサーバー内で他者が作成したマップも閲覧可能とし、自身の所属ギルドのマップだけに閲覧範囲を限定しません。閲覧できることと編集できることは別として扱います。
- 山岳データはギルドではなくサーバーに属します。対象サーバーの編集権限があれば、ギルドの選択有無にかかわらず山岳データを編集できます。

### 公開閲覧と編集者登録

- 未ログインの訪問者は、12文字の共有コード付きURLで指定サーバー内の全ギルドの地図を閲覧できます。全サーバー一覧は管理者のみ取得できます。共有リンクは個人別の閲覧許可とは異なります。
- Google ログインとアプリ用の表示名登録を完了した利用者は、編集停止されていない限り、誰でも登録済みの全サーバーを編集できます。サーバーごとの承認や担当ギルドによる編集範囲の制限は設けません。未ログイン、または表示名未登録の場合は閲覧のみです。
- 編集者はギルド選択の有無にかかわらず山岳情報も編集できます。各ギルドのメンバーが自分たちの地域の周辺を入力する運用を想定します。
- 利用者には、初回登録時にランダム生成と重複確認によって一意な識別名（例：`user-K7M4P9Q2`）を割り当てます。識別名は変更不能とし、メールアドレスや Google の識別 ID から直接生成しません。
- アプリ用の表示名は識別名やゲーム内プレイヤーのデータとは独立させます。初期値には Google のプロフィール名を使い、初回登録画面で確認・変更してから公開します。本人は登録後も変更可能です。表示名の重複は許容し、リネームの強制や名前への乱数の自動付加は行いません。
- Google ログインでは `openid profile` を要求し、`email` は要求しません。利用者のメールアドレスは取得・保存せず、不要なプロフィール情報や Google のトークンも保存しません。
- 認証には Google の識別 ID（`sub`）を使い、アプリ内部の利用者 ID・識別名との対応を非公開で管理します。公開履歴には Google の識別 ID やメールアドレスを含めません。Google の識別 ID も利用者情報として保護します。
- 編集履歴は、Google の識別 ID に対応する安定した内部利用者 ID にひも付けます。可読ログには保存時点の表示名と変更不能な識別名を使い、表示名が重複しても編集者を区別できるようにします。表示名の変更で過去ログを書き換えません。
- 管理者の表示は表示名ではなく実際の権限から付けます。管理者の初期登録もメールに依存しない手順へ変更します。
- 未登録サーバー番号を指定すると空マップを開き、編集権限者が初回保存すると新規登録します。共有データに個人情報や秘密情報を入力しないでください。
- Google ログイン・識別名・表示名登録・編集停止と、公開閲覧・共有保存のマップ API・画面への接続は実装済みです。さくら上の旧版からの移行手順は下記を参照してください。

### Undo・履歴復元・編集停止

- 保存前の Undo / Redo は、手元の編集を戻す・やり直す操作とし、共有データには影響しません。共有データの書き換えは明示的な保存時のみ行います。
- 保存ごとに版・更新日時・更新者を記録します。画面には表示中の版を明示し、保存前の変更があれば未保存状態を表示します。
- 保存後の復元は過去版を元に新しい版を作成し、復元者と復元元の版を記録します。既存の履歴は消去せず、版番号を巻き戻しません。
- 管理者は利用者単位で編集停止を設定できます。停止状態は表示名ではなく安定した内部利用者 ID にひも付け、表示名変更や再ログインでは解除されません。
- 編集停止中の利用者による共有データの変更は API 側で拒否します。履歴の復元による書き換えも編集として扱います。共有URLによる閲覧は引き続き可能です（管理者は共有コード不要）。
- 別の Google アカウントでの再登録を、同一人物として確実に判定することはできません。認証だけで荒らしを防げるとはせず、保存頻度の制限なども実装時に検討します。
- Undo / Redo・履歴復元・共有保存時の編集停止検査は実装済みです。メールを含む旧版データ・設定・バックアップ・ログの扱いは移行時に確認します。

### 要塞・前哨の配置状態と警告

- 基本的な作成手順は、まず要塞を配置し、その敷地内に前哨を配置して敷地を拡張する流れです。
- 通常領地は要塞の敷地を起点に計算します。その領地内に基準座標がある前哨の範囲を追加し、追加された領地内にある別の前哨へ順次拡張します。要塞→前哨→前哨という連鎖を許可し、前哨の番号や登録順に依存しない判定とします。
- 要塞につながっていない前哨同士が支え合っていても、通常領地とは認めません。要塞エリアとそこに連なる前哨の範囲のみを通常領地とし、断絶した前哨とその範囲は警告付きの予定配置として区別して表示します。
- 要塞未配置のギルドにある前哨の範囲も、通常領地ではなく警告付きの予定配置とします。予定配置の範囲は、ほかの前哨を通常領地につなげる根拠にしません。
- 要塞や前哨の移動・削除によって、前哨が敷地外となったり敷地が断絶したりする場合は、配置矛盾として警告します。通常の配置手順の条件と、編集中の状態を保存できることを区別します。
- ギルド一覧などで「要塞未配置」「前哨の配置矛盾あり」「正常配置」を区別して表示します。
- 矛盾のある前哨は、緩やかに点滅する赤いフレームやバツマークなどで位置を確認できるようにします。点滅だけに依存せず、静止した表示でも警告を判別できるようにします。
- 敷地の断絶や前哨の敷地外配置は警告であり、保存を拒否するエラーではありません。要塞未配置などの編集中の途中経過も保存可能とします。
- 座標範囲外、施設・山岳の重複、データ形式の不正などの検証エラーは、敷地に関する警告とは別に扱います。

### 全体表示での避難所の強調

- マップを全体表示したときも、自ギルド所属メンバーの避難所位置を点灯する目印として強調し、縮小表示でも所在を確認できるようにします。
- 強調対象は避難所の位置が自ギルドの敷地内かどうかではなく、プレイヤーの現在の所属ギルドで判定します。
- 広域表示ではグリッドや施設名を省略しても、この目印は表示します。

### サーバー内のユーザー名検索

- テキストボックスに入力したユーザー名の部分一致で、避難所位置を検索できるようにします。
- 検索対象は選択中のサーバー内に限り、そのサーバーの他ギルド所属プレイヤーも含めます。選択中のギルドだけには限定せず、サーバーを超えた検索は行いません。
- 複数の一致がある場合は候補を一覧表示し、対象を選んで避難所位置を確認できるようにします。

## マップのルール

- X:0〜511、Y:0〜1023。同じ奇偶の座標のみ存在し、入力・クリックは最寄りの有効座標へ丸めます。同距離の場合は小さい X、次に小さい Y を選びます。
- マップの範囲・配置・敷地の判定は座標値を優先します。
- 実験基地外囲の頂点は北(256,500)、西(244,512)、東(268,512)、南(256,524)です。
- 荒地の頂点は北(256,472)、西(217,511)、東(295,511)、南(256,550)です。各辺は45度の線分です。
- 外囲内の固定施設として、北部砲台(256,502)、西部砲台(246,512)、南部砲台(256,522)、東部砲台(266,512)（各2×2・南セル基準）を同じ色で塗り、凡例を表示します。西部砲台の占有セルは(245,511)、(247,511)、(246,510)、(246,512)です。編集・移動・削除はできず、共有データや施設選択一覧には含めません。中央の実験基地は基準座標(256,512)ですが、占有領域の輪郭が未確定のため、当面は描画しません。外囲の表示と外囲内への配置禁止は維持します。
- 2×2 施設の基準座標は南セルです。占有セルは `(x,y)`, `(x-1,y-1)`, `(x,y-2)`, `(x+1,y-1)` です。配置・移動時は4セルすべてを検証します。施設同士・山岳との重複は禁止です。
- 要塞・資源・トラップ・倉庫・病院は各ギルドに一つ。資源は種類・ギルドレベルを問わない単一の「ギルド資源」として扱います。避難所は所属メンバー一人に一つです。これらの施設は2×2です。
- 1×1 サイズの施設群
  - **ギルド前哨1〜ギルド前哨6**
    - 通常の配置手順では自身のギルドの既存の敷地内に配置します。配置されると、そのマスを中心としてギルドの敷地が拡張されます。敷地外となる編集中の状態は、上記の配置警告を表示したうえで保存可能です。
    - 前哨の基準座標から東西南北に各10離れた4点を頂点とする菱形の有効マスを敷地に追加します。`|ΔX| + |ΔY| <= 10` で描画・接続を判定し、境界を含みます。
    - (209,483)の前哨は、X:199〜219、Y:473〜493の範囲を追加します。西端は(199,483)、南端は(209,493)、北端は(209,473)です。
    - (264,436)の前哨は、X:254〜274、Y:426〜446の範囲を追加します。北端は(264,426)、東端は(274,436)です。
    - (257,443)の前哨は、X:247〜267、Y:433〜453の範囲を追加します。北端は(257,433)、西端は(247,443)です。
    - ギルド前哨1〜5の選択・配置・移動・保存・要塞起点の連鎖領地計算は実装済みです。未接続の前哨は赤枠・バツ印と件数警告で示し、領地を拡張しませんが計画配置として保存できます。ギルドごとの配置状態表示・未接続の予定領地の塗り分けは今後の課題です。
- 実験基地外囲と荒地は指定の頂点で判定します。境界セルも内側として扱います。避難所以外の施設は荒地に配置できません。山岳は荒地部分を除外して緑地に残る部分だけを配置します。避難所は荒地にも配置できますが、配置時に確認を表示します。実験基地外囲には避難所を含むすべての施設と山岳を配置できません。
- 要塞の南セルから東西南北に各12離れた4点を頂点とする菱形が領地です。`|ΔX| + |ΔY| <= 12` で描画・接続を判定し、境界を含みます。荒地・基地・山岳を除外します。自ギルドは明るい黄緑、他ギルドは暗い朱色、複数ギルドの共有領域は黄土色です。以前の四隅を含む矩形判定から変更したため、既存の前哨が未接続になる場合がありますが、座標の自動変更・削除や保存拒否はしません。
- 山岳群の座標はゲームサーバーによって異なるため、サーバーごとのデータとして管理します。山岳データは無名で、個々の山岳に名称は付けません。**山岳の実座標データは提供されていません。**「山岳（進入禁止）」で実際の位置を2×2単位で登録・移動・削除してください。JSON にも保存されます。架空の山岳位置は初期配置していません。
- 広域表示ではグリッドと施設名を省略します。拡大すると避難所のプレイヤー名・要塞のギルド名などが表示されます。

## 検証

### Google ログインの初期配置（PHP 8.3）

`api.php` はログイン・ログアウト・表示名登録と変更・管理者の編集停止管理ページと共有マップ API を提供します。

Google Auth Platform に外部・テスト用のウェブクライアントを作成し、管理者の Google アカウントをテストユーザーに追加します。スコープは `openid profile` のみで、メール・Drive・Gmail のアクセス権は要求しません。Google の戻り先には `https://vb-user.net/pns-map/api.php/auth/callback` を登録します。

SFTP で次のように配置してください。サーバーのパスは例です。アカウント名や秘密情報をリポジトリへ記録しないでください。

```text
/home/アカウント名/
  pns-map-private/                非公開：ディレクトリ権限 700
    config.php                   非公開：ファイル権限 600
    google-client.json           非公開：ファイル権限 600
  www/
    pns-map/
      api.php
      server/
        auth.php
```

1. `www` と同じ階層に `pns-map-private` ディレクトリを作ります。`www` 内には作らないでください。
2. 入手した Google の JSON を `google-client.json` という名前で、その非公開ディレクトリへアップロードします。クライアントの秘密情報が入っているため、チャットやリポジトリへ貼らないでください。
3. `server/config.example.php` をコピーし、`config.php` という名前にして非公開ディレクトリへ配置します。新規設置時は `admin_user_id` を `null` のままにします。メールアドレスの設定は不要です。
4. 公開側の `www/pns-map/` に `api.php`、`www/pns-map/server/` に `server/auth.php` を配置します。設定ひな型・テスト・Google JSON は公開側へ配置しません。PHP 公開ファイルの権限は契約先の指示に従ってください。
5. `https://vb-user.net/pns-map/api.php` を開いて「Google でログイン」を押します。Google プロフィール名が初期値として表示されます。公開してよい名前に変更して確定します。同名は許可され、変更不能な識別名で区別されます。
6. 新規設置では、自分の画面に表示された `user-` から始まる識別名を、非公開 `config.php` の `admin_user_id` に引用符付きで設定します（例：`'admin_user_id' => 'user-0123456789abcdef01234567',`）。SFTP で設定できる所有者だけが行う操作で、初めにログインした人を自動で管理者にはしません。再読み込みで管理者画面を確認します。
7. ログアウト・再ログイン・表示名の変更を確認します。別のテストユーザーで同じ表示名を登録でき、管理者画面からその利用者を編集停止・解除できることを確認します。

ユーザーの登録は Google の検証済み ID に基づきます。非公開領域に `users.json`・ロックファイル・`sessions-v2` ディレクトリが自動生成されます。Google の `sub`、不変の識別名、確定した表示名、管理者フラグ、編集停止状態のみを利用者情報に保存します。名前を確定するまでは Google プロフィール名は非公開セッション内だけに保持します。ログイン中も停止状態をレジストリから再確認するため、表示名変更・再ログインでは停止を回避できません。管理者の停止はこの画面では許可せず、非公開設定の保守で行うものとします。設定と利用者情報は非公開でバックアップしてください。

ログインは Secure / HttpOnly / SameSite=Lax の Cookie と非公開 PHP セッションで最大7日保持します。Cookie 削除・サーバー上のセッション削除などで早く終了することもあります。Google のアクセストークンや秘密鍵は localStorage に保存せず、セッションにも保持しません。Google ID トークンは公式の公開鍵で署名、発行者、対象クライアント、有効期限、nonce を確認します。OAuth state と PKCE を使い、ログイン開始・ログアウト・表示名変更・編集停止は CSRF トークン付き POST に限定します。Google への通信は証明書検証を有効にし、通信失敗時はログインを許可しません。

#### 既存のメール保存版からの移行

1. 旧 `api.php` を一時的に公開先から外して更新中のログイン操作を止め、`server/auth.php` と `api.php` を更新します。旧コードと新コードを同時に動かさないでください。
2. 非公開 `config.php` を上の新しいひな型に置き換えて、`admin_email`・`admin_servers` を除去します。Google JSON と戻り先 URL は変更不要です。
3. ページを開くと、`users.json` はロック下で自動移行されます。Google の `sub` を維持して一意な識別名を生成し、メールと旧サーバー別権限を除去します。旧レジストリでいずれかのサーバーの管理者だった利用者は、全体管理者として引き継がれます。移行後はこの権限を非公開で確認してください。破損データは上書きせずエラーとします。
4. 旧Cookieは新コードで使用しません。管理者は再ログインし、表示名を登録して管理者画面を確認します。既存管理者は `admin_user_id` の追加設定不要です。
5. SFTP で非公開領域の旧 `sessions` ディレクトリ内のセッションファイルを削除し、空になった旧ディレクトリを削除します。新しい `sessions-v2` は削除しないでください。`users.json`・Google JSON・設定は削除しないでください。
6. メール入りの古い設定コピー・利用者情報のバックアップ・手元のコピーがあれば、移行確認後に適切に削除します。サーバーの過去ログも確認し、保管・削除はホスティング側の手順に従います。自動移行が過去のバックアップやログまで消去することはありません。

表示名は1〜80文字（Unicode対応）で、制御文字を拒否します。同名・名前変更でも識別名・管理者権限・編集停止状態は変わりません。公開表示はHTMLエスケープします。表示名そのものも個人情報になり得るため、メールや本名などを公開したくない利用者には別名を使うよう案内します。

「ログイン処理を完了できません」となったら、画面の確認番号とサーバーの PHP エラーログで原因を確認します。秘密情報は共有しないでください。Google のエラーならテストユーザー登録・登録した戻り先 URL を確認します。`api.php/auth/callback` が Apache の404になる場合は、PATH_INFO の対応を別途確認する必要があります。

別ホストでは、Google 側の戻り先と `config.php` の `redirect_uri` を同じ HTTPS URL に変更します。Google JSON にも登録先が含まれるよう再ダウンロードしてください。非公開ディレクトリは既定で DOCUMENT_ROOT の親の `pns-map-private` です。環境変数 `PNS_MAP_PRIVATE_DIR` で変更できますが、公開領域内のパスは拒否します。セッションファイルは移設せず、利用者は再ログインしてください。

PHP がある環境では、`php -l api.php`、`php -l server/auth.php`、`php -l server/config.example.php` と `php server/auth.test.php` で構文・認証検証・初期権限を検査できます。CLI と proc_open が使えるローカル環境では `php server/api.test.php` でログイン開始・CSRF・コールバック拒否・ログアウトを検査できます。Google との実際のログイン、Cookie、Apache の PATH_INFO は配置先で確認してください。

### 共有マップ版の配置

認証設定済みのサイトへ、公開側の `api.php`・`server/auth.php`・`server/maps.php` と、`index.html`・`app.js`・`persistence.js`・`model.js`・`style.css`・`sw.js`・`manifest.webmanifest`・`icon.svg` を配置します。テストや設定ひな型・秘密設定は公開しません。更新中は旧 API を一時的に外して、コードの新旧混在を避けます。非公開設定・Google JSON・利用者情報は上書きしません。

`config.php` の `servers` は初期登録サーバーです。未設定なら **S1063** を初期登録として扱います。これに、非公開 `maps/S番号/head.json` に保存済みのサーバーを加えて登録一覧を作ります。編集権限者は任意の有効なサーバー番号を指定して新規保存でき、設定ファイルの書き換えは不要です。この配列はアクセス禁止リストではありません。

標準配置では非公開設定の場所は `/home/<account>/pns-map-private/config.php`（公開の `/home/<account>/www/pns-map/` の外）です。`PNS_MAP_PRIVATE_DIR` で変更している場合はその指定先を使います。画面からのサーバー削除・保存データの完全削除・登録禁止は未実装です。`servers` から番号を除くだけでは保存済みサーバーは非表示になりません。

地形の頂点は `model.js` とサーバー側の `server/maps.php` の両方を更新する必要があります。今回の地形修正版では両方更新済みです。旧データに荒地内の避難所以外の施設・山岳がある場合は、読み込み・保存時の配置検証に失敗する可能性があります。バックアップを保持し、JSONの座標を確認して修正してください。自動で施設を移動・削除しません。

`https://vb-user.net/pns-map/index.html` を開き、S1063 を確認します。API 接続に失敗した場合、端末内データに黙って切り替えずエラーを表示します。「最新版を読み込む」で再試行できます。更新前の画面が残る場合は、Service Worker 更新後に再読み込みしてください。

非公開領域に `maps/S1063/` などのサーバー別ディレクトリを自動作成します。各保存は変更不能な版 JSON を作り、最後に `head.json` を置き換えて公開版を切り替えます。処理中断で未参照の版ファイルが残る場合がありますが、通常履歴には含めません。削除・整理は今後の保守対象です。履歴数を自動削減せず保存するため、容量は監視してください。バックアップでは非公開の `maps` 全体を保存します。

API は `GET /maps`（サーバー一覧）、`GET /maps/S1063`（現行版）、`GET /maps/S1063/history`（最新100件）、`GET /maps/S1063/revisions/1`（過去版）を公開します。書き込みは `POST /maps/S1063` と `POST /maps/S1063/restore` で、セッション・CSRF・利用者レジストリの編集停止を確認します。保存時はv1をv2へ変換し、v2のプレイヤー・座標・地形・重複・所属・件数を検証します。ランクは所属ありの場合のみ任意の整数1〜5、前哨は `outpost1`〜`outpost5`・サイズ1として保存・検証します。プレイヤー管理版では `server/maps.php` も必ず更新してください。

`php server/maps.test.php` はサーバー間分離・保存・履歴・復元・編集停止・別プロセス間の競合保存を検査します。配置先ではログインして保存、再読み込み、未ログイン閲覧、別タブからの競合保存を確認してください。フォーム送信制限や WAF に拒否される場合はホスティング設定を確認し、全体の防御を無効化しないでください。

### さくらの PHP ホスティング確認

`hosting-check.php` は本番 API ではなく、一時的な環境検証ページです。アプリの静的動作には不要です。

1. PHP 8.3 に設定したサイトへ SFTP で接続します。
2. `hosting-check.php` を、ドキュメントルートの `www` 内（例：`www/pns-map/`）へアップロードします。PHP の配置については契約先の指示に従ってください。全員書き込み可能な権限は設定しないでください。
3. `https://vb-user.net/pns-map/hosting-check.php` をブラウザーで開きます（配置先に合わせて URL を変更してください）。
4. 「ファイル・ロック・セッションを検証する」を押し、結果を確認します。初回画面だけではファイル検証は実行されません。
5. 結果の項目名と OK / 要確認を控えたら、アップロードした PHP ファイルを削除します。

秘密鍵、パスワード、実データの設定は不要です。内部パス・環境変数・詳細なエラーは表示しません。ただし、このページ自体には利用者認証がないため、確認時だけ設置し、URL を広く共有しないでください。

公開領域外の書き込みは、PHP の `DOCUMENT_ROOT` が指す実ディレクトリの親に、一意な一時ディレクトリを作って確認します。既存データに触れず、作成したファイルとディレクトリを終了時に削除します。削除が「要確認」の場合は、SFTP で公開領域の親を確認し、今回作成された `pns-check-` で始まるディレクトリ内の `sample.json` / `replacement.json` とそのディレクトリだけを削除してください。ほかのディレクトリは削除しないでください。

この結果だけでは本番 API の安全性・移設性を保証しません。cURL / OpenSSL は利用可否のみ、flock は同一リクエストの別ハンドル間の競合のみを検証します。外部ログイン先との HTTPS 通信や、複数リクエストによる同時保存試験は実装時に行います。ローカルに PHP がある場合は `php -l hosting-check.php` で構文を検査できます。

`npm test` は Node.js 標準のテストランナーで座標・地形・占有・ギルド・メンバー・JSON 検証を実行します。`npm run check` は JavaScript の構文検査です。依存関係のインストールやビルドは不要です。
